## Next

- **GPU tests in CI.** Hosted runners have no GPU, so CI never exercises a kernel. Why: every GPU regression is caught only on the developer machine. Needs a self-hosted runner on an NVIDIA machine, triggered by push or workflow_dispatch only, never by pull requests from forks.
- **Grouped convolutions: odd per-group channels and small groups.** Per-group channel counts that are not a multiple of 16 (depthwise included) and groups whose products stay under f32ImplicitWorthwhile still use the one-thread-per-output kernel. Strides above 1 now take one implicit-GEMM launch per group, the input gradient through the subsampled gather. Why: depthwise layers are the common case of grouped convolution and still pay the slow kernel.
- **Strict f32 kernel efficiency.** What is left: a weight gradient that reads the output gradient transposed instead of going through transposeF32 (in f32 it cannot use ldmatrix and would need scalar copies into shared memory), and the stem (3 input channels) still builds an im2col matrix. Pairing the B loads into one 8-byte read measured slower and was reverted.
- **Skip the gradient zero-fill.** The zero arena is re-cleared every step (3.4% of a profiled bf16 CIFAR epoch). Design: Var gets a unique id, the tape finds the first writer of each gradient buffer before running backward, and each backward closure stores on the first write and accumulates after. Not started because it breaks the invariant that every backward closure adds into zeroed gradients, touches every op, and max-pool and convolution input gradients write only part of their buffer, so those still need the fill.
- **Batch 128 memory.** If a network ever approaches the scratch arena, bring back a --recompute flag that rebuilds the column matrix in the backward pass instead of keeping it. Why: the im2col paths keep their column matrices for the weight gradient.
- **Transformer heads as one product.** The twelve query, key and value projections of a step run at 0.87 TFLOPS f32 against 3.7 for a fused one, which saves about 175 us of a 9.7 ms step before the permute copies the split needs. Do it when a step is under 5 ms or the permute lands for another reason.
- **CPU convolution scaling.** Six threads give only 21.7% scaling efficiency on the MNIST CNN epoch (measured in one session, so not comparable with the README table). What is left at six threads is the 16->32 weight gradient (0.98 ms) and batch norm + ReLU (1.11 ms forward, 0.90 backward); both are bound by memory traffic and by the serial stretches (fc, optimizer, data). Packing A in the CPU tiled matmul was tried and reverted: it cost 5.3% on the CIFAR convolution GEMM and 9% on 4096x4096x64, which `bench` keeps as shapes.
- **ONNX GPU executor: Concat with many blocks.** A Concat takes one copy per input and outer index through the elementwise kernel (which writes only contiguous output) and goes to the host above 64 copies, so a concat along the last axis of a long sequence still bounces. A kernel with output strides would take any axis in one launch. Why: every bounce is a download, a CPU op and an upload. Slice, Div and Sqrt run on the device now; any op outside the list in src/onnx/gpu.zig still bounces too.
- **ONNX GPU executor: memory and layout.** Every activation of a run stays in the scratch arena until the next run, so the batch is limited by --scratch; freeing a tensor after its last user would lift that. A graph in the NCHW layout of other exporters pays two permutes around each convolution and pooling. Graphs imported from other frameworks have not been tried, only the hand-built NCHW graph in tests/onnx_gpu.zig. cuDNN is not used by the executor.
- **Multi-GPU on real hardware.** `--replicas` is checked against single-replica training only on one GPU. On several GPUs, test it, then replace the host round trip with device-to-device copies and average batch-norm statistics across replicas.
- **Linux GPU loader.** It compiles and CI runs its no-driver path, but it has never run against a driver; test it on a Linux machine with an NVIDIA GPU.
- **Mixed precision loss scaling.** bf16 does not need it, but an f16 path would.
