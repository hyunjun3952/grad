## Next

- **Grouped convolutions beyond stride 1.** Grouped stride-1 convolutions with a multiple of 16 channels per group run the implicit GEMM per group; grouped strides above 1, odd per-group channel counts and small groups still use the one-thread-per-output kernel. Why: grouped downsampling layers (stride 2) are common in mobilenet-style networks.
- **Fuse batch-norm statistics into the conv GEMM epilogue.** A re-measured profile of `cifar -Dbf16=true -- 1 --gpu --tensor-cores --profile` agrees with the earlier one: the implicit-GEMM convolutions take about 54% of the epoch, the batch-norm column reduction 9.6%, batch-norm grad input 6.3% and apply 3.9%, the zero arena memset 3.4%, the stem im2col 2.1% (one epoch 15.7 s). Why: the batch-norm statistics and application are over a fifth of the epoch and read or write the same feature maps the GEMM already touches.
- **Strict f32 kernel efficiency.** The 128 x 128 two-stage tile is in for the wide shapes; float2 B loads measured slower and were reverted. What is left: a weight gradient that reads the output gradient transposed instead of going through `transposeF32`, which in f32 cannot use `ldmatrix` and would need scalar copies into shared memory; and the stem (3 input channels) still builds an im2col matrix.
- **Drop `--recompute`?** With the implicit f32 GEMM only the direct path keeps column matrices (the stem and shapes whose channels are not multiples of 64), and the strict f32 peak is 470 MiB at batch 64. Measure batch 128 and the wide model without the flag; if both fit comfortably, remove the flag and `Gpu.recompute_columns`. Why: a flag that no longer matters is clutter, and the codebase should stay small.
- **Skip the gradient zero-fill.** The first writer of a gradient buffer could store instead of accumulate; the zero arena is re-cleared every step (3.5% of a profiled bf16 CIFAR epoch, a 262 MiB memset per step). It touches the backward pass of every op.
- **Transformer heads as one product.** Each head still has its own query, key and value projections and the heads are summed with add; one width x 3 * width projection, a permute op that splits heads into the batch axis and back, and batched products over batch * heads would replace about ten small launches per head and block. Needs a permute op with an ONNX Transpose export; the step graph already removed the launch cost, so measure first.
- **bf16 batched matmul in one launch.** The tensor-core path of a batched product packs and multiplies each matrix on its own (gpu.zig, matmul); a batch axis in tileGemm (blockIdx.z with strides, split-K moved elsewhere) would make it one launch. Only the bf16 Transformer uses it.
- **CPU convolution scaling.** The MNIST CNN takes 7.7 s per epoch on six threads after the row-wise max pool; profile what is left per layer on one and on six threads (packing of B in the small-n products, batch norm) before adding a direct loop that skips the column matrix.
- **ONNX runtime: NHWC convolutions.** Every exported convolution and pool is wrapped in two transposes (the engine is NHWC, ONNX is NCHW); the runtime could run NHWC Conv directly when it sees Transpose, Conv, Transpose, and the per-image im2col could cover the whole batch.
- **ONNX import on the GPU.** Imported graphs run on the CPU only. The runtime is NCHW with run-time shapes while the device kernels are NHWC, so a GPU executor needs NCHW kernels for im2col, pooling and batch norm, or has to recognise the exporter's Transpose, Conv, Transpose sandwiches as NHWC convolutions; copying each op's data to and from the host would make batch-1 inference slower, not faster. A new subsystem, not started.
- **Multi-GPU on real hardware.** `--replicas` is checked against single-replica training only on one GPU. On several GPUs, test it, then replace the host round trip with device-to-device copies (peer access or NCCL-style), and average batch-norm statistics across replicas.
- **Linux GPU loader.** It compiles but has never run; test it on a Linux machine with a driver.
- **Mixed precision loss scaling.** bf16 does not need it, but an f16 path would.
